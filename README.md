# 순천향대학교 졸업 길잡이

제공된 2026년도 SW융합대학 **학과기준 시안 PDF**를 근거로 질문에 답하고, 학생이 입력한 수강·활동 내역으로 **다면적 졸업인증**을 진단하는 Streamlit 앱입니다. 기존 프로젝트에 기능과 검증을 보완했습니다.

기본 선택: **순천향대학교 / AI·빅데이터학과 / 2022학번**. 학생 이수 기록과 점수는 미리 입력되어 있지 않습니다.

## 이클래스 제출본을 확인하는 교수님께

제출 ZIP 전체를 압축 해제한 후 바깥쪽의 **교수님_확인.html**을 더블클릭하면 Python 설치·로그인·인터넷 없이 질문 검색과 가상 진단을 체험할 수 있습니다. 이 HTML은 JavaScript 기반 간편 체험이며 Python·FAISS를 실행하지 않습니다. 실제 RAG 구현은 이 폴더의 Python 프로그램입니다. 온라인 체험: https://sch-grad-review-a143.raresparrow.chatgpt.site

실제 임베딩·FAISS를 확인하려면 아래 방법으로 원본을 실행하고 사이드바의 ‘다국어 임베딩 + FAISS’를 켜세요. 생성형 답변은 `.env`의 API 키와 ‘LLM 답변 사용’을 모두 설정해야 합니다. 기본 검색 모드·벡터 검색 모드·생성 모드를 구분하며, 생성형 API의 실제 응답은 키가 제공되지 않아 미검증입니다.

최종 재검증(2026-11-06): **177개 통과 / 실패·오류·건너뜀 0**. 상세 결과는 `test-results.xml`, 개선 내역과 미검증 범위는 `FINAL_AUDIT.md`를 확인하세요.

## 교수님이 원본 프로그램을 확인할 때

원본 앱의 첫 화면에서 **교수님: 가입 없이 실제 챗봇 확인**을 누르세요. 학생 학번·비밀번호 없이 동일 Python 프로그램의 PDF 단독 검색, 다중 PDF 업로드·검색, CSV/XLSX와 활동 기반 진단을 사용할 수 있습니다. 생성형 답변은 API 설정이 필요합니다. 업로드와 입력은 체험 세션 전용이며 ‘체험 종료’를 누르면 임시 PDF·인덱스·입력·결과를 정리합니다. 학생 계정 기록은 보이지 않습니다.

실제 검색 모드는 화면에 표시됩니다. **다국어 임베딩 + FAISS**를 켜야 벡터 검색을 사용합니다. 단순 HTML을 원본 RAG 서버로 설명하지 마세요. 서버 게시 준비 파일과 확인 순서는 `DEPLOYMENT.md`를 참고하세요. Docker 빌드와 실제 외부 Python 서버 게시는 별도 확인 전까지 미검증입니다.

## 이 컴퓨터에서 바로 실행하기

`No suitable Python runtime found`가 나오면 Python 런처가 Python 3.12를 찾지 못한 것입니다. `.venv` 생성에 실패했으므로 뒤의 `.venv\Scripts\python.exe` 명령도 실행되지 않습니다.

이 작업을 진행한 컴퓨터에서는 프로젝트 폴더의 **START_CHATBOT.cmd**를 더블클릭하거나 PowerShell에서 `./START_CHATBOT.cmd`를 실행하세요. 먼저 정상적인 `.venv`가 있으면 사용하고, 없으면 이 컴퓨터에서 확인한 기존 실행 환경과 작업 폴더의 설치된 패키지를 사용합니다. 8501~8520 중 빈 포트를 선택하고 서버 준비 후 브라우저를 자동으로 엽니다. 열리지 않으면 실행 창의 실제 주소를 복사해 브라우저에 붙여 넣으세요. 실행 중에는 콘솔 창을 열어 두세요.

기존 작업 폴더의 런타임·패키지가 없는 다른 PC에서는 아래 Python 설치 방법으로 진행해야 합니다. 실행 파일의 환경 검사 명령은 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_app.ps1 -CheckOnly`입니다. PowerShell 실행 정책은 이 프로세스에만 적용하며 시스템 설정을 바꾸지 않습니다.

## 1. 처음 설치하기

64비트 **Python 3.12**를 권장합니다. 실제 검증은 Windows의 Python 3.12.14에서 했습니다. 아래 명령은 압축을 푼 `graduation-rag-chatbot` 폴더 안에서 실행합니다. Python을 설치할 때 PATH 추가를 선택하세요.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --global.developmentMode false
```

가상환경 활성화가 필요 없는 명령이므로 PowerShell 실행 정책 변경은 필요하지 않습니다. `py`가 없으면 설치한 Python의 전체 경로를 사용하세요. Windows Store의 실행 별칭만 있고 Python이 설치되지 않은 경우 먼저 Python을 설치해야 합니다.

macOS/Linux:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py --global.developmentMode false
```

브라우저에서 [로컬 앱](http://localhost:8501)을 엽니다. 종료는 터미널에서 Ctrl+C입니다. 설치에는 인터넷이 필요하며 임베딩 모델 및 PyTorch 때문에 다운로드 크기와 설치 시간이 클 수 있습니다. 모델 다운로드 후에는 검색·계산을 API 키 없이 사용할 수 있습니다.

## 2. 첫 접속과 메뉴

학생 로그인 후 기본 메뉴는 **학과·졸업 통합 상담**입니다. 여기서는 제공 PDF와 확인한 학과 홈페이지 교육과정·연락처를 근거로 일상적인 문장으로 질문할 수 있습니다. **PDF 단독 RAG**는 홈페이지 자료 없이 해당 PDF만 검색합니다.

처음 접속하면 로그인 화면이 나옵니다. **회원가입 영역**에서 본인 학번·이름·학과·입학연도와 새로운 앱 전용 비밀번호를 등록한 뒤 로그인하세요. 로그인 후 사이드바에 이름과 학번이 표시됩니다. 학교 계정과는 별개의 과제용 앱 계정이며 학교 비밀번호를 입력하지 마세요. 학번으로 실제 재학 여부를 인증하지는 않습니다.

1. **PDF 단독 RAG**: 제공된 PDF만 검색합니다. 다른 PDF를 등록해도 이 모드에는 포함되지 않습니다.
2. **다중 문서 RAG**: ‘문서 등록 및 검색 상태’에서 PDF를 추가하고 전체 문서에 질문합니다. 동일 내용 중복 등록은 방지합니다. 새로운 PDF는 검색에 반영되지만 **진단 규칙은 자동 변경되지 않습니다**.
3. **졸업요건 진단**: 학과·학번을 선택하고 수강 파일 또는 직접 입력, 인증·활동 내역을 입력합니다. ‘이수 내역을 모두 입력했습니다’를 체크하면 미선택 항목을 미이수로 처리합니다. 체크하지 않으면 부족한 정보는 ‘확인 필요’입니다.
4. **진단 결과**: 최근 결과, 영역별 진행률·부족 점수·필수 항목을 확인하고 JSON을 내려받습니다. 결과에 사용된 학과·학번도 표시합니다.

5. **학과 안내**: 확인한 공식 학과 홈페이지·교육과정·학과사무실 링크와 PDF/제공 학사화면 차이 안내를 확인합니다. 홈페이지 자료는 PDF 단독 RAG의 검색 데이터에 섞지 않습니다.

사이드바의 **다국어 임베딩 + FAISS**를 켜면 무료 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`를 사용합니다. 최초 실행 시 Hugging Face에서 모델을 내려받습니다. 끄면 로컬 문서의 검수된 기준과 키워드 검색을 사용합니다. 벡터 준비 실패 시 검색 모드로 전환하고 오류를 표시합니다.

표 데이터는 학과·학번 단위로 구조화하여 청킹합니다. 출처·페이지·학과·학번 메타데이터와 검색 필터를 사용하므로 같은 페이지의 다른 학번 표를 답변에 섞지 않습니다. 일반 추가 PDF는 1,400자·250자 중복 청킹을 사용합니다. 추가 PDF의 적용 학과·학번이 명시되지 않으면 공식 적용 여부를 단정할 수 없습니다.

## 3. 선택 사항: LLM 설정

`.env.example`을 `.env`로 복사한 뒤 개인 키를 입력합니다. `.env`는 외부에 공유하지 마세요.

```dotenv
OPENAI_API_KEY=개인_API_키
OPENAI_MODEL=gpt-4.1-mini
EMBEDDING_MODEL=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
```

LLM 답변 사용을 켜면 LangChain의 API 연동으로 근거를 요약합니다. 모델 이름은 계정에서 사용 가능한 모델로 바꿀 수 있습니다. 키가 없거나 연결에 실패하면 근거 검색 답변으로 전환합니다. API 요청은 시간 제한 30초·자동 재시도 0회입니다. **점수 계산에는 LLM을 사용하지 않습니다.**

API 키가 없는 환경의 대체 기능은 검색 답변입니다. 별도의 로컬 생성형 LLM은 포함하지 않았습니다. 실제 유효한 API 키로 유료 요청을 보내는 검증은 수행하지 않았으며, API 예외 처리와 키 없는 경로는 자동 테스트했습니다.

## 4. 수강 과목 CSV / XLSX

`examples/courses.csv`를 참고하세요. 필수 열은 `과목명`, `이수 여부`이며, 공백을 제거한 `이수여부`도 지원합니다. 다음 열을 함께 넣을 수 있습니다.

```csv
과목명,이수 학기,취득 학점,이수 여부,성적,교과 영역
예비창업설계,2024-2,3,이수,A0,전공
수강신청과목,2026-2,3,미이수,,전공
```

- CSV는 UTF-8(BOM 포함 가능) 또는 CP949, XLSX는 첫 번째 시트를 읽습니다. 파일 크기는 5MB 이하입니다.
- 이수: `이수`, `완료`, `예`, `true`, `1`, `y`. 미이수: `미이수`, `아니오`, `false`, `0`, `n`, 빈 값.
- 성적이 F/NP/U이면 이수로 입력해도 제외합니다. 수강신청·진행 중 과목은 ‘미이수’로 입력하세요.
- 중복 과목은 한 번만 인정합니다. 띄어쓰기·유니코드 조합만 정규화하고 다른 과목명은 자동 대체 인정하지 않습니다.
- **취득 학점은 졸업인증 점수로 환산하지 않습니다.** 제공 PDF에 전체 졸업학점 규정이 없으므로 실제 졸업학점 합격 여부도 판정하지 않습니다.
- 중핵교양 국제사회언어영역의 개별 과목명 목록은 PDF에 없습니다. 해당 과목명과 학교 학사시스템의 영역 이수 확인을 함께 입력해야 5점을 인정합니다. 다른 필수 교과와 같은 과목을 중복 배정하지 않습니다.
- 파일이 잘못되면 오류 메시지를 보여주고 파일을 수정할 때까지 진단 실행을 막습니다.

## 5. AI·빅데이터학과 2022학번: PDF 5쪽

| 영역 | 필요 점수 | 검사 항목 |
|---|---:|---|
| 대학공통 | 45 | 인간사랑 5, ASP(1·2학기) 5, 자기주도상담 5, 자기개발과전공탐색 5, 졸업필수활동 15, 현대기본영어 5, 봉사학습 5 |
| 교과 | 10 | 예비창업설계 5, 중핵교양 국제사회언어영역 택1 5 |
| 비교과지정 | 21 | 학과활동 5, 자격증/경진대회 6, 코딩역량인증 Level2 이상 5, AI·SW전공역량졸업인증 5 |
| 비교과미지정 | 19 | 공감 5, 창의 4, 글로벌 10 |
| 합계 | **95** | 모든 필수 항목과 각 인재상 조건을 함께 검사 |

학과활동은 **회당 1점**으로 5점까지 필요 점수에 반영합니다. 2022학번에는 TOPCIT이 지정 필수 항목으로 명시되어 있지 않습니다. 2023~2026학번은 교과 5점·지정 비교과 26점이며 TOPCIT 응시 5점이 포함됩니다. 총점이 같아도 구성은 다릅니다.

권장 자격증 취득은 6점입니다: 데이터아키텍처전문가, SQL전문가, SQL개발자, 데이터분석전문가, 데이터분석준전문가, 빅데이터분석기사. 화면에서 PDF 표기 그대로 선택합니다. SQLD/ADsP 같은 약칭은 자동 과목·자격 대체 처리하지 않습니다.

경진대회 참가는 3~10점, 수상은 10~30점의 범위만 PDF에 있습니다. 대회별 배점은 임의로 정하지 않습니다. **학교에서 확정한 인정 점수와 확인 여부**가 필요합니다. 참가와 수상 또는 자격증과 대회를 임의로 중복 합산하지 않고, 확인된 한 경로가 해당 6점 조건을 충족하는지 검사합니다. 복수 대회의 부분 점수 합산으로만 조건을 채우는 사례는 별도 공식 확인이 필요합니다.

자율활동도 개별 활동의 배점표가 없어 학사시스템의 **공감·창의·글로벌 각 영역 공식 인정 점수**를 입력합니다. 사용자가 확인한 점수임을 결과에 표시하며 시스템과 실시간 연동하지 않습니다. 예를 들어 공감 4점·글로벌 11점으로 공감 부족 1점을 상쇄하지 못합니다. 자료 미확인 시 ‘확인 필요’입니다.

진단 화면에서 학사시스템에 표시된 **필요 점수**를 별도로 입력하면 PDF와의 차이를 보여줍니다. 이 값으로 PDF 규칙을 덮어쓰지 않습니다.

‘충족’은 **다면적 졸업인증 충족 예상**입니다. 전체 졸업 가능 여부는 항상 별도로 **확인 필요**입니다. 원본이 ‘1차 시안’이므로 최신 확정본·학교 학사시스템과도 대조해야 합니다.

## 6. 문서와 규칙 관리

- 원본 PDF는 `data/`에 포함되어 있습니다. 원문을 변경하지 않았습니다.
- `data/`는 제공 PDF와 관리자가 넣은 공통 자료입니다. 다중 문서 메뉴에서 추가하는 PDF는 현재 계정의 전용 폴더에 저장되며 다른 계정의 검색에 포함되지 않습니다(30MB 이하). PDF 단독 모드는 추가 PDF를 제외합니다. 개인 수강 내역은 진단 메뉴의 CSV/XLSX로 입력하세요. 손상·암호화·텍스트 없는 PDF는 안내 메시지를 표시합니다. 이미지 PDF는 먼저 OCR이 필요합니다. 과거 버전에서 `data/`에 직접 넣은 파일은 계속 공통 자료이므로 개인 문서라면 별도로 옮겨야 합니다.
- 내용 해시가 바뀌면 인덱스 키가 바뀌고 새 검색 데이터가 생성됩니다. 모델명·규칙 변경도 인덱스에 반영합니다.
- `.index/`에는 FAISS 벡터와 JSON 문서를 저장합니다. pickle 역직렬화는 사용하지 않습니다.
- 여러 문서의 총점이 다르면 불일치를 표시합니다. 일반적인 규정 의미 충돌을 모두 자동 검출하는 시스템은 아니므로 문서별 근거를 함께 확인해야 합니다.
- 진단 규칙은 `rules/graduation_rules.json`에 있습니다. 새 PDF의 규정은 사람이 원문을 검수하고 적용 학과·학번·페이지·필수 항목을 등록해야 합니다. API가 규칙을 자동 생성하거나 덮어쓰지 않습니다.
- 6개 학과·21개 학번 구간을 등록했습니다. 일부 타 학과의 어학·자율활동·대체과목 세부 배점이 없어 확인 필요로 남습니다. 자료가 없는 학번도 판정하지 않습니다.
- 앱 계정과 사용자가 저장한 입력·진단 결과는 로컬 SQLite에 저장합니다. 학사시스템 실시간 연동은 포함하지 않습니다. 채팅은 현재 로그인 세션에서만 보관하며 로그아웃 시 지웁니다. 진단 JSON도 내려받을 수 있습니다.

## 11. 추가 사용성·판정 보완

- **지난 결과 구분:** 학과·학번별 결과를 따로 보관합니다. 입력, 규칙 JSON 또는 등록 문서가 바뀌면 지난 결과임을 알리고 재진단을 안내합니다. 결과 JSON에는 UTC 진단 시각과 입력·기준·문서의 지문이 포함되며, 화면 시각은 KST로 표시합니다.
- **다음 행동 안내:** 부족 점수와 함께 추가 상담·활동 횟수, 필요한 인증 수준, 미이수 과목, 공식 확인할 항목을 표시합니다. 이 안내는 기존 PDF 규칙으로 계산하며 새 규정을 만들지 않습니다.
- **유사 과목 처리:** 유사한 과목만 입력한 경우 점수를 주지 않고 해당 필수 과목을 ‘확인 필요’로 구분합니다. 공식 대체 인정이 확인된 경우에만 PDF의 정확한 과목명으로 수정하세요. 유사 후보조차 없는 미입력 필수 과목은 ‘미충족’입니다.
- **확인 값 검사:** 증빙 확인 여부에 문자열 `"false"`가 들어와 참으로 처리되거나, 이수 여부에 5점 같은 숫자가 들어오는 잘못된 입력을 거부합니다. 지원하지 않는 규칙 종류도 오류로 알립니다.
- **대화 유지:** 학과·학번·단독/다중 문서 범위별 대화를 구분해 세션 안에 보관합니다. 메뉴를 오가도 대화가 유지되며 ‘현재 대화 지우기’로 해당 대화만 지울 수 있습니다. 문서나 규칙이 바뀌면 새 문맥으로 시작합니다.

새 모듈 `src/diagnostic_state.py`는 입력 지문·진단 시각·지난 결과 판별을 담당하며 `tests/test_improvements.py`와 UI 회귀 테스트로 검증합니다. 사용자가 저장하거나 진단한 입력과 결과는 같은 앱 계정으로 다시 로그인하면 복원됩니다. 채팅 기록은 세션에만 보관합니다.

## 12. 계정과 개인 입력 저장

- 첫 계정 관련 작업 시 `.local/accounts.sqlite3`를 생성합니다. **기본 계정·기본 비밀번호·실제 학생 점수는 없습니다.**
- 비밀번호는 무작위 salt와 PBKDF2-HMAC-SHA256(600,000회)으로 저장하며 평문으로 저장하지 않습니다. 같은 비밀번호도 계정마다 다른 해시가 됩니다.
- 로그인 실패 5회 시 해당 학번의 로그인을 5분 제한합니다. 계정·입력 저장 쿼리는 매개변수를 사용합니다.
- 로그인한 사용자의 학번으로만 저장된 입력을 불러옵니다. 로그아웃하면 화면 상태·대화·다른 학생의 진단 기록을 세션에서 지웁니다.
- **입력 저장**을 누르거나 **나의 졸업인증 진단**을 실행하면 현재 학과·학번의 입력과 결과가 저장됩니다. CSV/XLSX 원본 파일 대신 이수 완료된 과목명만 보관합니다.
- 저장된 업로드 과목을 제거하려면 파일 선택을 해제한 뒤 **저장된 업로드 과목 비우기**를 누르고 입력을 다시 저장하세요.
- 사이드바에서 현재 비밀번호를 확인한 뒤 비밀번호를 변경할 수 있습니다. 이메일을 사용한 비밀번호 찾기는 구현하지 않았습니다.
- 이 앱은 학교 SSO·차세대종합정보시스템에 로그인하지 않습니다. 자기신고형 과제 계정이며 학교의 공식 인증 서비스가 아닙니다.
- `GRADUATION_APP_DATA_DIR` 환경변수로 데이터 디렉터리를 지정할 수 있습니다. 해당 폴더를 유지해야 계정과 저장 기록을 복원할 수 있습니다.
- `.local/`, SQLite 파일과 `.env`는 제출 ZIP에 포함하지 않습니다. 실제 사용자 DB를 과제 제출 파일이나 공개 저장소에 넣지 마세요.
- 로컬 과제 실행을 검증했습니다. 공개 서비스 배포를 위한 HTTPS·계정 복구·운영자 관리·외부 인증 연동은 별도 범위입니다.

## 13. 한국어 / English / 简体中文 / 日本語

화면 상단의 **언어 / Language**에서 언어를 바꿉니다. 로그인·회원가입, 주요 메뉴와 입력, 상태, 점수 표를 4개 언어로 제공합니다. 과목·자격증 이름은 원문과 함께 표시하고 저장 키와 규칙 계산은 한국어 원본으로 유지합니다.

- 주요 화면과 **추천 질문**은 API 키 없이 동작합니다.
- 영어·중국어·일본어의 기본 졸업요건·점수 질문을 오프라인 주제 사전으로 한국어 검색어로 바꿉니다. 지원하지 않는 단어를 임의로 버려 엉뚱한 주제로 답하지 않습니다.
- 자유로운 문장 번역과 답변 요약은 `.env`의 API 키와 **LLM 답변 사용**이 필요할 수 있습니다. 실제 유효한 키를 이용한 생성·번역 호출은 미검증입니다.
- 번역은 이해를 돕는 보조 표시입니다. 원문 근거와 파일명·페이지·수치는 함께 표시합니다. 일부 상세 원문·확인 안내는 한국어로 남을 수 있습니다.
- 개인정보인 이름·학번·비밀번호를 번역 API에 자동 전송하지 않습니다. 사용자가 입력한 질문과 해당 문서 근거는 LLM 옵션을 켰을 때 API로 전송될 수 있습니다.

## 15. 학생과 교수·평가자 입구

처음 화면에서 **접속 유형 → 학생 / 교수·평가자**를 선택합니다. 로그인과 회원가입은 탭 없이 좌우 영역에 표시합니다.

- **학생:** 기존과 같이 학번과 앱 전용 비밀번호를 사용합니다.
- **교수·평가자:** 학번이 필요 없습니다. `professor1` 같은 평가용 아이디, 이름, 새 앱 전용 비밀번호로 가입합니다. 아이디는 영문으로 시작하는 4~40자이며 영문·숫자·밑줄·점·하이픈을 사용할 수 있고 대소문자를 구분하지 않습니다.
- 교수·평가자로 로그인하면 **교수용 과제 평가**가 첫 메뉴입니다. 비어 있는 기록, 일부 이수, 확인 가능한 조건 충족, 필수 과목 누락, 자율활동 부족, 정보 미확인 등 가상 사례로 판정을 확인합니다. PDF 단독 RAG 메뉴에서 직접 질문할 수도 있습니다.
- 가상 사례는 실제 학생 기록을 조회하지 않고 학생별 저장 결과에도 반영하지 않습니다. 평가용 가입이 학교의 교수 신분 인증이나 학생 기록 열람 권한을 뜻하지 않습니다.
- 기존 계정 DB에는 `role` 열만 추가하고 학생 계정과 저장 기록을 유지합니다. 학생과 평가자의 아이디는 서로 다른 공간에서 관리합니다. 학교 SSO·교직원 인증·성적 처리 기능은 연결하지 않았습니다.

### 로그인 제목만 보이고 입력란이 안 보이는 경우

로그인/회원가입의 탭 의존성을 제거했습니다. 서버 PowerShell에서 **Ctrl+C**를 누른 뒤 `./START_CHATBOT.cmd`로 다시 실행하고, 브라우저에서 **Ctrl+F5**로 새로 불러오세요. 원래 설치된 정적 화면 파일의 누락·해시 불일치는 발견하지 못했습니다. 실제 브라우저의 재확인은 접근 승인 제한으로 수행하지 못했으므로, 새로고침 후에도 입력란이 없으면 서버의 최신 오류 출력과 새 화면을 확인해야 합니다. AppTest로 입력란이 생성되는지는 검증하지만 이것만으로 모든 브라우저의 렌더링 성공을 보장하지 않습니다.

## 16. 일상적인 질문과 통합 상담

‘정확한 문구’만 검색하던 제한을 보완했습니다. 다음처럼 질문할 수 있습니다.

- `코딩역량 인증제 조건이 뭐야`
- `졸업하려면 뭘 해야해?`
- `학과 활동은 몇 번 해야돼?`
- `22학번 졸업 요건 알려줘`
- `코딩이랑 학과활동 조건이 뭐야`
- `그럼 몇 점이야?` — 앞선 한 가지 항목과 학과·학번을 이어서 확인합니다. 여러 항목 뒤의 모호한 질문은 대상을 다시 묻습니다.
- `우리 학과 사무실 전화번호 뭐야` — 통합 상담에서 확인한 공식 홈페이지 연락처로 답합니다.
- `3학년에는 무슨 과목 배워?` — 통합 상담에서 학과 홈페이지 교육과정으로 답합니다. 입학연도별 졸업 필수목록이라고 단정하지 않습니다.
- `예비창업설계 몇 학점이야?` — 홈페이지의 교과 학점과 PDF의 졸업인증 점수를 구분합니다.
- `내 점수 알려줘`, `나 졸업 가능해?` — 같은 로그인 계정·학과·학번의 저장된 개인 진단이 있으면 해당 결과를 안내합니다. 진단이 없거나 입력이 변경되었다면 먼저 진단/재계산을 요청합니다. 개인 점수는 LLM이 새로 산정하지 않습니다.

근거가 충분한 항목은 조건과 출처를 먼저 짧게 표시하고 **근거 원문 보기**에서 전체 표 정보를 확인합니다. 없는 시험 일정·응시 방식은 만들지 않고, 확인 가능한 인증 기준과 부족한 자료를 구분합니다.

**어떤 질문에도 사실을 만들어 답하는 기능은 아닙니다.** 자료가 없는 졸업학점, 최신 시험일, 대체 인정 규정, 개인의 공식 졸업 확정은 확인할 수 없습니다. 자유로운 생성형 요약과 번역은 LLM API 연결을 선택하면 사용할 수 있지만, 답변 근거는 등록된 자료로 제한합니다.

통합 상담용 홈페이지 정보는 `references/department_guide.json`에 2026-11-05 확인본으로 저장했습니다. 실시간 웹 크롤링은 하지 않습니다. 원본 링크를 열어 바뀐 내용을 확인한 뒤 사람이 갱신할 수 있습니다. 새 규정이 생겨도 이 JSON으로 졸업인증 계산 규칙을 덮어쓰지 않습니다.

새 파일: `src/advisor.py`(대화·후속 질문·개인 결과·짧은 답변), `src/department_guide.py`(공식 홈페이지 자료), `references/department_guide.json`, `tests/test_advisor.py`.

### 자유 질문의 LLM 보완 경로

API 키를 설정하고 **LLM 답변 사용**을 켜면, 기존 키워드 검사에서 검색되지 않은 질문도 선택 학과·학번의 검수된 PDF 표를 직접 읽고 답하도록 보완했습니다. 원래 질문을 유지하고 학교 규정의 빈 부분을 추측하지 않도록 지시합니다. 근거에 없는 새로운 수치가 응답에 나타나면 답변을 보류합니다. 이 검사는 의미상 모든 오답을 검출하는 완전한 보증은 아닙니다.

API 키 없이도 일상 표현 처리·짧은 조건 답변·홈페이지 교육과정과 연락처·개인 진단 조회는 동작합니다. 실제 유효한 키로 생성형 응답을 받는 검증은 수행하지 않았고, 요청 내용·범위·수치 거부 처리는 테스트 대역으로 검사했습니다. 추가 파일: `src/freeform.py`.
